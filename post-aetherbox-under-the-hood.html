UNDER THE HOOD

2026-09-12 · AETHERBOX · 7 MIN READ

AetherBox is an official fork of Droidspaces by ravindu644 — credit where credit is due. The core idea is his: a single static binary that sets up Linux namespaces on Android and then steps aside. What I've been doing is hardening it for the messy reality of real phones.

Why a static musl binary

Under 400KB, linked against musl libc, no runtime dependencies. On Android that matters more than elegance: there is no glibc to link against, no package manager to lean on, and every OEM ships a slightly different userspace. A static blob either runs or it doesn't — usually it runs.

Booting an init system on a phone

Starting a shell in a chroot is easy. Booting systemd is not: it wants PID 1, a writable /sys/fs/cgroup, /proc mounted fresh, a tmpfs on /run, and a working dbus socket. So the runtime creates the namespaces, mounts that set in the right order, then hands PID 1 inside the new PID namespace to init. After that systemctl, journalctl and socket activation all behave like a normal machine.

OpenRC, runit and s6 are lighter and want less — they're the better choice on low-RAM devices.

The cgroup v1 fallback

Plenty of phones still ship kernel 4.x with cgroup v1 only, sometimes with a hybrid layout an OEM invented. Instead of demanding v2, the runtime probes what is actually mounted and falls back to v1 controllers automatically. That one behaviour is the difference between "works on my Pixel" and "works on a five-year-old budget phone", which is the point of the project.

Where things still break

  • SELinux. Some OEM policies block mounts even as root; permissive or a policy patch is needed.
  • Kernels without user namespaces. Nothing to do but recompile the kernel.
  • Aggressive OEM process killers. The container is fine; Android just murders the app.
  • Loop device limits. Image-backed rootfs needs free loop devices, which some kernels cap low.

Handy commands inside a container

DEBUGGING A CONTAINER
systemctl --failed
journalctl -xb --no-pager | tail -40
cat /proc/self/cgroup
mount | grep cgroup

What's next

More rootfs images in the curated repo, better desktop presets, and cutting the first-unpack time. If your device fails in an interesting way, send me the logs — odd devices are how this thing got good.
